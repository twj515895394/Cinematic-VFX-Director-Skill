## 功能验收步骤
每个案例必须经过：
1. 原始 `source_prompt` 原样交回且编译期间没有修改输入卡片。
2. 非侵入式模式 `compiled_prompt` 仅包含该卡已有的 `vfx_delta`。
3. 原子 ID 真实存在于上游 566 词库中，ID 不泄露到用户可复制的提示词。
4. `events` 各自包含触发、锚点、视觉和反馈字段，Schema 能验证。
5. 未提供 `--approved`，或 Card 仍为 `vfx-only` 时，**任何整合请求必须被拒绝**。
6. 用户同时批准且 Card 显式放开整合范围后，输出仅是“原始文本 + 新增 VFX 段落”，原始文本必须是完整前缀。

执行：

```bash
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
python scripts/compile_prompt.py --card sample.sword-activation
python scripts/compile_prompt.py --card sample.sword-activation --json
```

## 额外的导演级人工检查
上述测试验证的是**数据与输出安全**，不能仅凭结构判断“效果有电影感”。交付前由 Agent 按 [director-workflow](../references/director-workflow.md) 与 [combination-gates](../references/combination-gates.md) 继续审核以下问题：
- 主效果是否真的服务剧情/镜头信息，是否只有一个 Primary 重点？
- 源/触发/轨迹/实际接触/受体反应/最终状态是否构成因果链？
- 风格审美与载体是否匹配，例如柔光、2D冲击帧不能被误读为世界观魔法？
- 服装、武器、人数、摄影机位、时长、原动作是否全部保持不变？
- 不必要的粒子、爆闪、冲击波、离体弹、法阵有没有被及时删去？
- 是否忽略相机景深、遮挡、接触可读性、自然光和相邻表面的光照？

发现问题时只给最小修复建议，不擅自重写用户原稿。**P3 不是自动视觉 QC 引擎；影片级评测及独立审片属于 P6。**
