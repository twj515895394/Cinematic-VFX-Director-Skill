# P5 · 用户不熟悉 VFX 时：先推荐 3–5 方案，再确认

> 本章为 Cinematic VFX Director Skill 的**默认新手交互入口**。专业术语只在 Agent 检索和审计层使用；对用户先说明“画面会出现什么”，而非强行介绍 VFX 原子分类。

## 一、触发条件

当用户只给**视频场景、已有提示词、图片、参考视频或分镜**，要求“加点特效”“提升电影感”“帮我配特效”，而没有明确选择想要的 VFX 种类时：

**必须先分析，输出 3–5 个真正适合这个画面的备选方案并等用户确认；不得跳过确认阶段就擅自写定最终特效。**

例外：用户已经明确说“就在剑刃加紫色流光，不要其他方案”，可直接执行；术语学习和故障诊断也不强制套推荐菜单。用户希望“不加特效”也应尊重，不能为了凑菜单添加错误特效。

## 二、Agent 如何从模糊输入作出判断

1. **从用户真实提供的信息提取场景事实**：角色、动作、道具、场景、镜头、摄影/动画风格、已有光源、节奏、时长、禁改项；记录未知部分。使用图片时只描述可见事实，单张静图中不可凭空确认“人物将拔剑/攻击”，也不要将示例图片文字当作真实观察。
2. **定位四维**：medium、genre、style、vfx family。先查 `data/profiles/cinematic_profiles.json` 和 `scripts/lookup_profile.py`，再读取 upstream 的原始效果、物理、分层、亮度与媒介规则；必要时使用 `scripts/search_atoms.py` 在566条原始 VFX 原子中检索。动漫游戏动态案例仅对匹配的二维动效可用，不能直接拿来冒充真人电影特效。
3. **列候选而不是术语堆叠**：选择3–5个有不同视觉目标的候选，避免同一个“辉光”的五种同义说法。每个候选讲清：**看到的画面、为什么适合当前镜头、能量/空间锚点与触发、相对强度、可能的副作用**。至少保留一个克制方案；强烈奇幻方案仅在用户设定允许时出现。用户明确禁止的效果一律不推荐。
4. **排序但不替用户做决定**：在最合适的一项旁标“推荐”，但不预先选中。结尾说“你选 A1/A2/...，也可以要求组合或选择不加特效”。如果可能，展示小范围组合选项（例如剑表面能量 + 手部受光），但不要两个 Primary 同时抢焦点。
5. **停在选择阶段**：第一次回复不得假装 Agent 已拿到批准，也不生成最终 MiniMax H3/Seedance 成片提示词。可将候选输出为 `data/schemas/recommendation-package.schema.json` 契约，其中 `selection_state=awaiting-user-selection`。
6. **用户选择后**（例如“选A2”“A1+A3，A1为主”“按推荐的来”）才结合选中的方案编写/审核 Effect Card，补具体动作时间点、接触与环境反馈，按 `references/combination-gates.md` 做最小变动。若用户选多个，明确主次，检查冲突与人物/道具变形风险。
7. **模型适配**：用户没说就 MiniMax H3；用户明确要 Seedance 才走 Seedance。参考 `references/model-adapters.md` 输出模型定向 VFX 增量。已有原稿默认逐字保留，整合稿仍须遵循 P3 授权双门禁。
8. **后续反馈**：用户可能选择“太夸张”“再微弱一点”“能不能换成光学效果”，此时只调整已选方案对应的 VFX 强度与组合，不重写原剧本/剪辑。

### 典型人性化回复示例

用户：「这张人物握剑的半写实CG图片帮我加点特效。」

Agent：先告诉用户**只观察到了握剑姿势，未来是否挥剑尚不明确**，再给3–5项，例如：

- **A1｜剑刃逐步亮起**（推荐）：紫色能量贴着原有剑刃流动，指节与衣袖被轻微映亮；适合表现“力量苏醒”，不增加攻击。
- **A2｜剑周薄雾扰动**：仅在剑附近出现轻雾和流动空气，神秘而不抢焦点；注意不要遮挡手指。
- **A3｜剑面能量凝聚**：剑纹内出现短促凝聚光泽，适合增强奇幻感；需控制光色以保住原剑材质。
- **A4｜柔光材质反射**：改善剑身与皮肤的高光层次，电影感更克制；不等于凭空加一束强光。

收尾：「你更喜欢 A1–A4 哪个？也可以说‘A1为主，搭配A4’，或‘先不加特效’。确定后我再整理成 MiniMax H3 的视频特效提示词。」

上述为**创作示例**，不是在当前对话中对真实图片的鉴定；实际用户提供图片时须重新观察、重新匹配候选，不可机械套固定方案。

## 三、可运行的结构门禁

```bash
python -m pip install -r requirements-dev.txt

# Agent先据真实图片/场景写出一份推荐包。以下只是3个测试样例：
python scripts/recommend_options.py --package examples/recommendations/sword-image.json
python scripts/recommend_options.py --package examples/recommendations/rainy-street.json --json

# 只有用户明确选了A1，才运行下一步：
python scripts/recommend_options.py --package examples/recommendations/sword-image.json --select A1 --user-confirmed --json
```

脚本**不会读取或理解图片本身**，也不会自动挑选特效。它校验 3–5 个备选的结构、原始566词库ID、模型范围、确认状态，输出面向用户的推荐文本或已确认的方案 brief。Agent 负责视觉理解、专业选型、Effect Card 设计和最终说明，不要把静态测试包冒充真实图片自动分析结果。

## 四、质量与异常处理
- 信息不足时可以在方案上标明条件：“如果现有画面有积水，则增加涟漪；否则不加”。不要推断不存在的对象、光源、动作或神话世界观。
- 如果用户原本就是要一个极其具体的特效（或已经选完），不要强制重复3–5轮选择。
- 用户只给一张图时，首帧参考与人物身份锁定优先，不能将图片视为完整动态动作线索。
- 当没有合理特效时，可明确建议不加；“推荐 3–5”不是给不可用的场景凭空制造视觉噪声的借口。
- 用户选择后不代表同意改写其他剧本要素；默认仍仅输出独立 VFX 增量。
